# 案件概要書 → 初期検討サマリー

友井が初期検討で担当するのは `投資条件` タブの**青塗り12項目＋基本情報3項目**だけ。
青以外（No.6 投資リターン／No.7 事業計画／No.10 競合差別性／No.13-15）は他メンバー
担当なので、**判定しない**。触れる場合も「担当外」と明記する。

判定の閾値は `references/rubric.md` が唯一の正。数字が出る項目は必ず
`scripts/score.py` に通し、目で判断しない。

## 手順

1. **読む** — PDF/xlsx/docx/画像いずれでも、まず全文を取り出す。
   数字は「どのページのどの表から取ったか」を控える（後で根拠列に書く）。
   `売上`（直近期）と `平均必要運転資金` は概要書に直接書かれていないことが多い。
   売上は損益計算書、運転資金は3期分のBSから
   `売上債権＋棚卸（仕掛工事含む）−仕入債務` を各期算出して平均する。
2. **数値を埋める** — `scripts/inputs.example.json` を雛形に JSON を作る。
   概要書に無い項目は **キーごと省略する**（0 を入れない。0 は「ゼロという事実」、
   欠落は「未確認」で、判定が真逆になる）。
3. **機械判定** — `python3 scripts/score.py deal.json`。
   定量6項目（1-2／1-3／2／3／5／11）と総合判定が出る。
4. **定性判定** — 残る6項目（1-1／4／8-1／8-2／9／12）を rubric の定義に当てて
   自分で付ける。根拠は概要書の記述に紐づけ、推測で埋めない。
5. **出力** — 下の3ブロックをこの順に返す。

## 出力フォーマット

### ブロック1 基本情報
| 項目 | 内容 |
|---|---|
| 案件名／仲介会社 | |
| 価格 | 希望株式価値、算定根拠（○倍、純資産+営業権 等） |
| 進行期業績 | 売上・実態EBITDA見込み、前期比 |
| 意向表明期限 | 日付（記載なければ「未提示」） |

### ブロック1.5 数値サマリー（管理表転記用）
`譲渡価格 / EBITDA / EV/EBITDAマルチプル / 売上` の4項目。`score.py` が
タブ区切りの1行も出すので、ソーシング管理表の hot案件シートにそのまま貼れる。

マルチプルは**TE定義（EV＝譲渡価格−実質NetCash）を主**として出し、仲介が提示して
くる簿価NetDebtベースの倍率も参考として併記する。両者は運転資金の扱いだけで
大きく開くことがあるので、どちらの数字の話をしているかを必ず明示する。

売上は目安レンジ 300〜3,000百万円（投資条件友井タブ No.20）の範囲内かを添える。
これは青塗り外の項目なので ◯△× は付けず、参考表示にとどめる。

### ブロック2 評価表
`No / 評価軸 / 評価 / 根拠（1行） / 確認事項` の6列。行順は rubric と同じ12行固定。
評価は `◯ / △〜◯ / △ / ×〜△ / × / －` の6値のみ。`－` は情報不足で判定不能。
根拠は**必ず1行**。長い説明は確認事項に回す。

末尾に `総合判定：A／B／C` と達成率、Must項目（1-1・1-2・2・5）の結果を1行で。

### ブロック3 仲介会社への質問リスト
`－` と `△` 以下が付いた項目から、そのままメールに貼れる箇条書きを作る。
案件を落とす前提でも作る（次の案件で同じ質問を使い回すため）。

## 守るべきこと

- **不明は `－`。推測で◯や×を付けない。** 概要書だけで価格判定まで到達できる案件は
  少ない。`－` が多いこと自体が「情報開示の質」の情報になる。
- **×が1つでも Must 項目に付いたら、そこで総合C。** 他項目の◯で埋め合わせない。
- 概要書に守秘義務の記載があれば、社名・所在地を出力に書かない（業種と規模のみ）。
- 数字の単位は概要書の表記を維持し、百万円/千円/円を勝手に揃えない。揃える場合は
  揃えたと明記する。

## EV/EBITDA の閾値について

3つの資料で数字が違う（`投資条件` タブ7倍／`投資条件友井` タブ5倍／仲介会社様向け
資料6倍）。rubric はこれを1本の段階評価に畳んである（◯=5倍以下、△=7倍以下、
×=8倍超）。**どれか1つに統一する決定が出たら rubric を直す。**
