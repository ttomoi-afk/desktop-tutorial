# 買収に実際に必要な金額（所要資金）

譲渡価格は支出の一部でしかない。初期検討では「いくらで買うか」とは別に
**「譲渡日にいくら用意するか」** と **「回収後にいくら残るか」** を分けて出す。

算出は `scripts/cash_need.py` に任せる。目で足さない。

```bash
python3 scripts/cash_need.py deal.json
```

## はしご

```
  ① 株式取得対価                 譲渡価格
  ② 承継コスト                   仲介手数料＋DD費用＋法務・登記
  ③ 譲渡時に返済する借入          LBOローン／個人保証付き借入／役員借入金
  ④ 運転資金の積み増し
  ⑤ 承継後1年の設備更新投資
  ⑥ その他の初期費用             システム統合・名義変更 等
  ─────────────────────────────
  【A】譲渡日に用意する額 ＝ ①〜⑥

  ⑦ 余剰現預金（戻り）           現預金 − 対象会社に残す手元資金
  ⑧ 非事業資産の売却（戻り）      保険積立金・投資有価証券・遊休資産
  ─────────────────────────────
  【B】ネット所要資金 ＝ 【A】− ⑦ − ⑧
  　− 買収借入
  ＝ TE自己資金拠出額            ← No.1-2 の4億円と比べる数字
```

**【A】と【B】は別物。** 譲渡日には【A】の現金が要る。⑦⑧の回収はその後なので、
【B】だけを見ているとブリッジが足りなくなる。

## 簿価NetCash の1本値では作れない

同じ `NetCash ＝ +200` でも中身が違えば別の案件になる。

| | 現預金 | 有利子負債 | 譲渡日に要る額への効き方 |
|---|---|---|---|
| 無借金型 | 200 | 0 | 返済不要。余剰現金を回収できる |
| 両建て型 | 1,200 | 1,000 | 1,000の返済資金が当日要る。個人保証の解除交渉も付く |

**案件管理には現預金と有利子負債を分けて記録する。** NetCash は差額として出す。

## 対象会社に残す手元資金

既定は**月商1ヶ月**（`sales ÷ 12`）。現預金をここまで抜ける前提で⑦を計算する。
運転資金が重い業種、季節性のある業種、前受金で回っている業種は個別に置き直す。
現預金が必要手元資金を下回る場合は、承継直後に資金注入が要るので警告が出る。

## 既存借入は「返済」か「承継」か

**この前提だけで所要額が借入額そのまま動く。** 既定は全額返済（保守側）。

| 状況 | 扱い |
|---|---|
| LBOローン、売主個人保証付き借入 | 返済・借換が前提（`debt_repay` 既定） |
| 代表者からの役員借入金 | 返済。価格に含まれている場合は①との二重計上に注意 |
| 金融機関がCOC条項で期限の利益喪失を定めている | 返済 |
| 上記以外で金融機関が承継に同意 | `debt_repay: 0` で承継 |

**必ず両方を出して並べる。** 仲介に確認するまでどちらか決まらないことが多い。

## 不動産の持ち方

不動産を持つ案件は、同じ価格でも3通りの資金の作り方がある。

| | 所要資金への効果 | 代償 |
|---|---|---|
| (a) そのまま承継 | 変わらない。時価×掛目70%が買収借入の担保余力になる | なし |
| (b) 譲渡対象から外す | 株式価値を時価分下げられる | 年 時価×6% の賃料が実態EBITDAから落ちる |
| (c) 承継後にセール＆リースバック | 売却代金を回収 | 同上。譲渡所得課税と担保解除の同意が要る |

利回り6%・掛目70%は既定値。`cap_rate` `ltv` で変えられる。

## 簿外・偶発債務

本体には足さず別掲する。顕在化したら上乗せになるもの。

- 未払残業（労働集約・長時間業種）
- 退職給付引当不足
- 前受金・預り金の返金義務（回数券・デポジット・入居一時金）
- 減価償却の未計上
- 係争・行政処分

## No.1-2 との関係

rubric の No.1-2 は `TE拠出額 ＝ 株式価値 ＋ 承継コスト − 買収借入` と定義しており、
**③の返済借入と⑦の余剰現預金が入っていない。** そのため所要額ベースの評価と
ずれることがある。ずれたら、両方を出したうえで判断を仰ぐ。黙ってどちらかに寄せない。
