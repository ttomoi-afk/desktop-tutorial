# 一次情報（メルマガを除く）を数えて案件管理表に入れる

案件管理に載るのは友井がノンネームシートから選んでネームクリアを依頼した案件だけ。
その手前の母数＝**仲介会社が友井・sourcing@ 宛てに直接送ってきた案件情報**を `一次情報` タブに
1案件1行で残し、仲介会社管理シートの右端（月次の一次情報・年間一次情報計・ネームクリア率）が
それを数える。行の判断は下の定義だけに従い、件数は必ず `tools/make_inflow_blocks.py --verify` で
シートの式と突き合わせてから渡す。

## 1行の定義

- **1行＝1案件**。その案件の情報が最初に届いたメール（NN、ティーザー、本文の匿名概要、NNへのリンク、
  それが最初なら IM・概要書）の日付で入れる。挨拶スレッドの途中で添付されてくることが多い。
- 同じ仲介の同じ案件は1回だけ。IM・概要書・パスワード通知・質疑・日程調整・再送は続報なので足さない。
- 1通で N 件なら N 行（件名は同じになるので `案件の要点` で見分ける）。
- 当社がバトンズ等で問い合わせた案件に仲介が返信してきたものも入れる（経路＝問い合わせへの返信）。
- 送信者が社外で、To か Cc に友井か sourcing@ があるメールだけ。社内転送は数えない。

**メルマガ（入れない）**：号・一覧形式の一斉配信。「○月○日配信」「新着 N件」、定型で複数案件を並べる、
配信用アドレス（news. / info@ / mag@ / nn_info@ など）、友井個人への呼びかけが無い、
「名刺交換した方・メルマガ登録者へ配信」「システムから自動送信」の記載。
これまでに確認した配信元：インテグループ（news. の「新規M&A売却案件のご紹介」）、オンデック（新着譲渡案件）、
M&Aキャピタルパートナーズ（info@ の【M&A情報】）、日本M&Aセンター（《新着N件》）、
経営承継支援（「名刺交換・お問い合わせの方へ配信」とある一斉配信）、たすきコンサルティング（新着M&A譲渡案件）。

**メルマガではない（入れる）**：担当者が名前を出して友井様／Team Energy 様宛てに特定の案件を紹介しているもの。
HubSpot・Salesforce など配信ツール経由で配信停止リンクが付いていても、個別の紹介なら入れる
（例：ソーシング・ブラザーズ各担当の「株式譲渡案件のご紹介」、プレックスの mashien.com 経由の紹介、
ACN経営研究所の sfcustomeremail.com 経由の紹介）。

## 手順

1. **正本を取る** — 案件管理表（ドライブのGoogleスプレッドシート）を xlsx でダウンロードして `live.xlsx` にする。
   `一次情報` タブがあれば最後の受信日を見て、その翌日から集める。
2. **メールを読む** — Gmail は読み取り専用で使う（ラベル・既読化・送信はしない）。
   仲介会社のドメインごとに `from:<ドメイン>` で全スレッドを出し、`get_thread`（MINIMAL）で中まで見る。
   スニペットで分からない添付メールだけ `get_message`（PLAIN_TEXT）で開く。最後に週ごとに受信を総当たりして、
   知らない送信者からの紹介が無いか確かめる。件数が多いときは仲介会社のまとまりごとにサブエージェントへ分ける。
   **sourcing@ だけ宛てのメールは友井の受信箱に届かない**（2026/11時点）。そちらの分は数えられていないと必ず書く。
3. **案件管理と突き合わせる** — ネームクリア済みの案件なら `案件管理No` を入れる。
   推定で入れるときは案件管理の事業内容と業種・地域が合うことを確かめる（社名がメールに無いことが多い）。
4. **rows.json を書く** — キーは一次情報タブの見出しそのまま（No は書かない）。仲介会社は
   仲介会社管理シートA列の正式名称。A列に無い会社は `new_brokers` に書く（打ち間違いはエラーで止まる）。
   `メール` には `https://mail.google.com/mail/u/0/#all/<スレッドID>` を入れる。
5. **ブロックを作って検算する**

   ```bash
   python3 tools/make_inflow_blocks.py --layout live.xlsx --rows rows.json \
           --out out/blocks_MMDD_一次情報.txt --verify
   ```

   初回はタブの追加と、仲介会社管理シートへの列の追加・見出し・式のブロックも出る。
   `--verify` は貼った後の状態で式を評価し、仲介会社×月の件数が rows から数えた件数と一致するか見る。
   **失敗0で、表の件数が納得できてから渡す。**

## 守ること

- 案件は秘密保持の対象。社名・案件名で Web 検索しない。rows.json・ブロックは `out/` か作業用の
  ディレクトリに置き、リポジトリに入れない。このファイルにも実案件の社名・担当者名・個人のアドレスを書かない。
- ネームクリア率が100%を超える仲介会社は、一次情報の取りこぼし（sourcing@ 宛て、面談で口頭、別の社員宛て）を疑う。
